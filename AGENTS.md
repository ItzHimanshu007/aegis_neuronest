# AGENTS.md — Aegis non-negotiable invariants

This file governs every change to this repository, by a human or by an agent.
If a task appears to require breaking one of these rules, **the task is wrong** — stop and ask.

Read [`docs/architecture.md`](docs/architecture.md) for what we are building and
[`docs/STAGES.md`](docs/STAGES.md) for what is in scope right now.

---

## The invariants

### 1. Raw page data never leaves the browser

Input values, raw text, raw screenshots, cookies, storage, and page `id`/`class` names stay local.
Page `id` and `class` names are included in this rule because they are high-entropy fingerprints and
frequently contain user data.

### 2. There is exactly one network path

`extension/net/network.ts → send(payload: SanitizedPayload)` is the only way to reach the server.

- `SanitizedPayload` is a **branded type**. Only `extension/privacy/firewall.ts → seal()` may create one.
- `send()` additionally checks a **runtime registry** of sealed payloads, so a type assertion is not
  enough to get past it.
- `health()` is the only other permitted request: `GET /health`, carrying no page data.

### 3. Tokens

Tokens look like `[[PII:<TYPE>:<8 chars base32 lowercase a-z2-7>]]`, generated by **HMAC-SHA-256**
with a **non-extractable**, per-session Web Crypto key.

Token-like strings found in page text must be **neutralized before sealing**, so a hostile page
cannot smuggle a token into the plan.

The pattern lives in exactly one place — `TOKEN_PATTERN` in `extension/shared/schema/tokens.ts` —
and is mirrored in `server/app/schemas/tokens.py`. Never re-type the regex.

### 4. Re-hydration is narrow

A token is restored to its real value **only**:

- inside a `type` action,
- into a field whose type **matches the token type**,
- on the **origin the user consented to**.

Never in URLs, never in navigation, never in keys, never anywhere else.

### 5. Redaction

Text PII is **only ever solid-filled**. **Blur is used only for faces.** Never pixelate text —
pixelation is reversible.

### 6. The server only proposes

The extension validates, reacquires, re-hydrates and executes. **Never execute code or selectors sent
by the server.** The `plan.v1` schema has no field that can carry either, and it must stay that way.

### 7. No remote code

No remote code, no `eval`, no `new Function`. All models are bundled or cached locally.

### 8. Secrets are in-memory only

Never write the token vault, the session key, or raw values to `localStorage`, `IndexedDB`,
`chrome.storage.local`, or logs. `chrome.storage.session` is allowed for **non-secret** state only.

### 9. Every stage adds tests

Nothing is "done" unless **`pnpm check`** passes: typecheck, ESLint, Vitest, server `ruff`, server
`pytest`, and schema fixture validation.

### 10. Do not work ahead

Implement the current stage only. Everything else is a stub marked `TODO(stage-N): ...`
(`# TODO(stage-N)` in Python). Stubs that could silently do the wrong thing should throw instead.

### 11. End every stage with a STAGE REPORT

Format:

```
STAGE REPORT — Stage N
1. Summary (5-10 lines)
2. File tree (depth 3, excluding node_modules/.venv/dist)
3. Commands run + results (install, build, check, web-ext lint) — paste key output lines
4. Generated manifests: Chrome and Firefox (full JSON)
5. Manual verification done (what you could and couldn't verify, e.g. browser loading)
6. Deviations from this prompt + reasons
7. Known issues / warnings
8. Questions for the next stage
```

## Enforcement that already exists

| Invariant | Enforced by |
| --------- | ----------- |
| 2 | ESLint `no-restricted-syntax` bans `fetch` / `XMLHttpRequest` / `WebSocket` outside `net/network.ts`; branded type; runtime `WeakSet` registry |
| 3 | Single exported `TOKEN_PATTERN`, mirrored server-side and tested for agreement |
| 7 | ESLint bans `eval` / `new Function`; no remote script hosts in the manifest |
| 9 | `pnpm check` |

Enforcement is not decoration. If you add a bypass "just for a test", the test is the bug.

## Conventions

- TypeScript **strict**; no `any` that crosses a module boundary.
- Contracts live in `/shared/schema` as **JSON Schema draft 2020-12** and are the single source of
  truth. TS types are generated (`pnpm gen:types`); Pydantic models mirror them and a test proves
  the two agree on the fixtures.
- Extension: React for **side panel UI only**. Content scripts are plain TypeScript.
- Python: 3.12, `uv`, `ruff`, `pytest`, pydantic v2.
- Both browser targets are **MV3**. WXT may default Firefox to MV2 — it is forced to MV3, and the
  generated manifests are checked.
